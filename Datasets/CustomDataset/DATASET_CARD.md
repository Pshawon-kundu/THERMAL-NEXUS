# Dataset Card — Custom THERMAL-NEXUS

## Summary

| Field | Value |
|---|---|
| Dataset name | thermal-nexus-custom-v1 |
| Version | 1.0 (2026-07-31) |
| Source | Software simulation only |
| Generated by | `simulator.temperature.generator.generate_run` |
| Split policy | Stratified group K-fold by `run_id` |
| Label type | 3-class (STABLE / TRANSITION / EXCURSION_RISK) |
| Primary task | Early-warning classification on cold-chain logger data |
| Modality | Tabular sensor time-series |
| Sample frequency | 1/60 Hz (1 minute per row) |
| Schema version | v2 (see `ml/features/feature_schema.py`) |

## Provenance

- The **synthetic temperature traces** were produced by the
  `simulator.temperature` package from the YAML scenario config in
  `config/scenarios.yaml`. Each scenario defines a thermal envelope (start
  temperature, environmental drift, event schedule, noise) and the simulator
  draws samples from the corresponding stochastic process.
- The **labels** are derived from the simulator's true temperature at
  configurable future horizons (5, 10, 15 minutes) per
  `config/labeling.yaml`. They are *not* human annotations.
- The **features** are extracted by `ml/features/extract_features.py` from the
  raw temperature. They include rolling statistics, distance-from-limit, and
  validity flags. The schema guard
  (`ml/features/feature_schema.py`) rejects any leakage-prone columns.

## Composition

- **96 runs**, 12 scenarios × 8 seeds. Each run is a 7,200 s (2-hour)
  temperature trace sampled at 60 s.
- **Feature rows**: 12,584 (after expanding the lookahead windows).
- **Splits**: 78 train / 13 validation / 13 test runs (no shared `run_id`).

## Use cases

- Train the embedded logistic-regression classifier used by the C99
  parity/embedded-ML pipeline.
- Train the decision-tree, random-forest, and small-MLP reference models.
- Calibrate the on-node event-driven policy (`simulator/sensor_node/policy.py`).

## Out of use

- Hardware validation. The temperature values are simulated.
- Real-world drug safety. The model is not a substitute for validated
  cold-chain compliance processes.

## Update policy

- Changes to scenarios or label policy require regenerating this dataset.
- Side effects must propagate to `ml/data/splits/` and the
  `ml/models/selected/latest_selected.json` artifact.

## Limitations

- No human-in-the-loop review.
- No real-world temperature gradient diversity (lab conditions only).
- Distribution is dominated by the `gradual_warming` and `door_opening`
  scenarios; some rarer faults (e.g. `sensor_drift`) have fewer labelled
  EXCURSION_RISK rows.
